An **Agent** is a lightweight service that runs on the target host where your Docker containers are deployed. It connects to the Hub via WebSocket, receives deployment instructions, and reports status back. You can run multiple agents. One agent per environment, server, or cluster.

## Creating an Agent

Before deploying the Agent, you need to register it in the Hub to obtain an authentication token.

1. Navigate to the **Agents** page in the OrcaCD UI.
2. Click **Add Agent** and give it a name (e.g., `production`, `staging`) and optionally an icon.
3. Copy the generated `AUTH_TOKEN` (only shown once).

![Create Agent](/assets/docs/create-agent.png?url)

## Deploying an Agent

### Same Host as the Hub

The default `docker-compose.yml` includes both Hub and Agent. If you are running both on the same machine, just set the `AUTH_TOKEN` in your `.env` and restart:

```bash
docker compose up -d
```

### Remote Host

To deploy an Agent on a separate server, copy only the Agent service definition to that machine. See [installation](/docs/setup/installation) for instructions on how to set up the Agent service.

The Agent will connect to the Hub. Once connected, its status in the Hub UI changes to **Online**.

<Callout>The Agent needs access to the Docker socket to manage containers on the host.</Callout>

### Hub with a Private CA

If the Hub uses a self-signed certificate or a certificate from a private CA, mount the CA certificate into the Agent container and set `CA_CERT_FILE` to its path. The certificates are added to the system CAs. See [environment variables](/docs/configuration/env-variables#agent).

## Multiple Agents

You can register as many agents as you need. For example, one per environment:

| Agent name   | Purpose                       |
| ------------ | ----------------------------- |
| `production` | Deploys to the production VPS |
| `staging`    | Deploys to a staging server   |
| `dev`        | Local development environment |

Each Application in OrcaCD is assigned to exactly one Agent. You can split workloads across agents freely.

## How the Agent Deploys

For every application, the Agent creates a directory `<DEPLOYMENTS_DIR>/<project>/` (by default `/deployments/<project>/` inside the Agent container) containing:

- `compose.yaml`: the Compose file from your repository.
- `compose.override.yaml`: generated by OrcaCD. It adds the labels `managed_by=orca-cd` and `orca-cd.application-id=<id>` to every service. The file is rewritten on every deployment, so manual changes are overwritten.

Because the override file is loaded automatically, a manual `docker compose up` in this directory keeps the OrcaCD labels.

The Compose project name `<project>` is derived from the application name: it is lowercased, every character other than `a-z`, `0-9` and `_` is replaced by `-`, repeated dashes are collapsed and leading or trailing dashes are removed. For example, `My App` becomes `my-app`. The Agent refuses to deploy to or remove a Compose project with the same name that was not created by OrcaCD.

Before deploying, the Agent checks the Compose file against the [deployment policy](/docs/advanced/security#compose-deployment-policy).

## Rotating an Agent Token

If a token is compromised or needs to be rotated, navigate to the Agent in the UI, open the options menu, and select **Rotate token**. A new token is generated immediately, the old token becomes invalid and a running Agent is disconnected right away.

Update the `AUTH_TOKEN` in the Agent's `.env` and recreate the container:

```bash
docker compose up -d
```

## Deleting an Agent

Deleting an Agent removes it and all of its applications (including their history) from the Hub and disconnects the Agent.

<Callout type="warn">
	Deleting an Agent does **not** remove the containers of its applications from the host. To remove
	them, delete the applications while the Agent is still online, or remove them manually on the host
	afterwards.
</Callout>

## Agent Status

| Status    | Meaning                                                                                       |
| --------- | --------------------------------------------------------------------------------------------- |
| `Online`  | Agent is connected and ready to receive deployments                                           |
| `Offline` | Agent has disconnected or has not yet connected                                               |
| `Error`   | Agent is connected but cannot reach its Docker daemon. Deployments fail until it is reachable |

If an Agent is offline, deployment dispatch fails immediately and the application is marked out-of-sync with an error. Deployments are not queued or retried automatically. Trigger the deployment again once the Agent is back online.

### Connection

The Hub sends a ping to all Agents every 60 seconds. If the Agent does not hear from the Hub for about 150 seconds, it drops the connection and reconnects. When the Hub restarts, all Agents are marked offline until they reconnect.

When an Agent disconnects, the health of its applications changes to `Unknown`, and deployments that were still running are marked as failed.

Offline [notifications](/docs/advanced/notifications) are only sent after the Agent has been disconnected for 60 seconds, so short reconnects (e.g. Agent restarts or token rotation) do not trigger them.

## Versions

The Agents page shows the **Agent Version** and **Docker Version** reported by each Agent. The Agent reports them when it connects and whenever the Docker daemon becomes reachable or unreachable.

| Badge         | Meaning                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| `Outdated`    | The Agent is older than the Hub. Update it to get the latest features and fixes                         |
| `Unsupported` | The Agent is older than the minimum version supported by the Hub. Update it to keep deployments working |
| `Unknown`     | The Agent has not reported its version, e.g. because it has not connected since the Hub was updated     |

If any Agent is outdated or unsupported, an alert is shown at the top of the Agents page. See [Upgrading](/docs/setup/upgrading) for how to update an Agent.
