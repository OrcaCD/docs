An **Application** in OrcaCD represents a Docker Compose deployment. It links a repository (and a specific branch and file path) to an Agent, which runs the actual containers.

## Overview Dashboard

The **Overview** page shows the status of all applications, recent deployments and agents at a glance and lists the applications that need your attention, e.g. because they are unhealthy or their last deployment failed.

![Overview dashboard](/assets/docs/overview-dashboard.png?url)

## Creating an Application

Navigate to the **Applications** page, click **New Application** and select the Agent, the repository, the branch and the Compose file. The name must be unique per Agent, because the Docker Compose project name is derived from it.

OrcaCD reads the Compose file from the latest commit of the branch and immediately deploys it to the selected Agent.

## Application Details

The details page of an application shows its [status](#application-status), the repository, the deployed commit, the Agent and what triggered the last sync. Below, you can see the current Compose file and a diff to the previous version.

## Application Status

Each application shows two status indicators:

### Sync Status

| Status        | Meaning                                                                                                                          |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `Synced`      | The last deployment, sync or image update succeeded                                                                              |
| `Out of Sync` | The last deployment, sync or image update failed or was interrupted (e.g. the Agent disconnected or the Hub restarted during it) |
| `Syncing`     | A deployment or image update is currently in progress                                                                            |
| `Unknown`     | No deployment has finished yet                                                                                                   |

New commits are not shown as out of sync: as soon as OrcaCD sees a new commit (depending on the [sync strategy](/docs/advanced/architecture/repositories#sync-strategies) of the repository), it deploys it automatically. If an application is `Out of Sync`, check the error on the details page or in the [history](#history) and deploy it again.

### Health Status

The health is reported by the Agent, which watches the Docker events of the application's containers and updates the status in real time.

| Status      | Meaning                                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `Healthy`   | All containers are running and none of them reports a failing Docker healthcheck                                                |
| `Unhealthy` | At least one container is not running (e.g. restarting) or reports a failing Docker healthcheck                                 |
| `Stopped`   | All containers are created, exited or paused, e.g. after `docker compose stop`                                                  |
| `Unknown`   | No containers exist, a healthcheck is still starting, a deployment is running, the Agent is disconnected or cannot reach Docker |

## Triggering a Deployment

OrcaCD automatically deploys when the tracked repository branch receives a new commit that changes the Compose file (depending on the repository sync strategy), and when image polling or the image pull webhook detects a new image. You can also trigger a deployment manually from the details page:

| Action              | Description                                                                                                                            |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Deploy**          | Redeploys the current Compose file without syncing the repository                                                                      |
| **Sync repository** | Available in the dropdown next to **Deploy**. Fetches the latest commit and deploys the changes to all applications of this repository |
| **Pull images**     | Available in the dropdown next to **Deploy**. Pulls the latest images and redeploys only if an image changed                           |

<Callout>
	The Agent must be online to deploy. If it is offline, the deployment fails immediately and the
	application is marked `Out of Sync` with an error. Deployments are not queued or retried
	automatically, so trigger the deployment again once the Agent is back online.
</Callout>

## History

The **History** page of an application records every deployment, commit sync and image update with its time, trigger, the user who triggered it, the commit, the result (`Running`, `Succeeded`, `Failed` or `No change`) and error details.

You can switch between a table and a timeline view. The search filters the history by type, trigger, result, user, commit hash or message, and error message.

![Application history in the timeline view](/assets/docs/application-history-timeline.png?url)

## Application Settings

### General

Change the name, icon, Agent, repository, branch and Compose file of the application, or delete it.

Saving does not deploy the application. If you change the Compose file, the Agent or the name, a notification with a **Deploy** button appears so you can apply the changes right away.

![Deploy prompt after saving changes](/assets/docs/deploy-after-edit-toast.png?url)

When you move the application to another Agent or rename it so that its Compose project name changes, OrcaCD first removes the old containers from the current Agent. Deleting an application also removes its containers and deployment directory from the Agent. Both require the current Agent to be online. Otherwise the request fails with `409 Conflict` and nothing is changed.

![General settings of an application](/assets/docs/application-general-settings.png?url)

#### Delete old images

When enabled, OrcaCD removes the images an application no longer uses after every successful deployment, image update and manual image pull. Images are removed by ID, so this works both for changed tags and for new digests of the same tag. Images that are still used by other containers are kept.

### Image Updates

![Image update settings](/assets/docs/application-image-updates.png?url)

#### Image Polling

Image polling lets OrcaCD automatically pull updated Docker images and restart containers, even when the Compose file has not changed. This is useful for mutable tags like `latest` or for CI pipelines that push new images under the same tag.

The polling interval is at least 60 seconds (default: 120 seconds).

The Agent compares the images of the application with the registry. If any image changed, it pulls the images and redeploys the application.

If the check fails, for example because the Agent has no credentials for a private registry, the application changes to `Out of Sync` and the error is recorded in its history. Repeated failures with the same error are only recorded once. The next successful check sets the application back to `Synced`. See [common issues](/docs/troubleshooting/common-issues#deployment-is-stuck-in-syncing) for registry credentials.

#### Image Pull Webhook

Instead of polling, your container registry can notify OrcaCD via a webhook when a new image is pushed.

1. Open the **Image Updates** settings of the application.
2. In the **Image Pull Webhook** section, click **Generate Webhook**.
3. Copy the secret. It is only shown once. The webhook URL is shown afterwards in the settings.
4. Register the webhook in your container registry. See [Webhooks](/docs/configuration/webhooks#container-registries) for the setup of Docker Hub, GitHub Packages, Harbor and generic registries.

When a webhook is received, the Agent pulls all images of the application and redeploys it if any image changed. Deliveries for the same application are combined: the pull starts once no further delivery has arrived for 5 seconds, but at the latest 30 seconds after the first one. This way, one push that triggers several webhooks only results in one deployment.

Click **Regenerate** to create a new secret or **Revoke** to disable the webhook. The old secret stops working immediately.

<Callout>
	The Agent must be online for the image pull webhook to succeed. If the Agent is offline, the event
	is not queued.
</Callout>
