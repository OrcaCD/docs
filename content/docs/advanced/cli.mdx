## Hub

The Hub binary includes a CLI for administrative tasks that cannot be performed through the web UI. Run any command with `--help` to see all available options.

When using Docker, prefix commands with:

```bash
docker compose exec hub /app/hub <command>
```

Use `docker compose exec` while the Hub is running. Commands that require a stopped Hub (`import` and `key rotate`) are executed with `docker compose run --rm hub <command>` instead. The image entrypoint is already `/app/hub`, so the binary path must not be repeated there.

<Callout>
	Most commands do not require an interactive terminal. For commands that require confirmation
	`--yes`/`-y` can be used as CLI flag to confirm dangerous operations.
</Callout>

### export

Creates a consistent backup of the Hub database. The export uses SQLite's `VACUUM INTO` and is safe to run while the Hub is running.

```bash
hub export [--output <path>]
```

| Flag             | Default                         | Description                     |
| ---------------- | ------------------------------- | ------------------------------- |
| `-o`, `--output` | `hub-export-YYYYMMDD-HHMMSS.db` | Output path for the backup file |

Relative paths are resolved inside the `data/` directory, absolute paths are used as given. The command refuses to overwrite an existing file.

**Usage with Docker:**

```bash
docker compose exec hub /app/hub export
```

The file is created inside the container under `/app/data/`, which is mounted to `./data/hub/` on the host with the default `docker-compose.yml`. Copy it from there to include it in your backup strategy:

```bash
cp ./data/hub/hub-export-*.db ./backups/
```

### import

Restores a database from a backup file. The existing database is copied to a rollback file (`<database>-restore-<timestamp>.bak`) before the restore, so you can recover if something goes wrong. Backups created by a newer OrcaCD version are rejected.

<Callout type="warn">
	The Hub server must be **stopped** before running import. All existing data is overridden by the
	backup.
</Callout>

```bash
hub import <file> [--yes]
```

| Argument / Flag | Description                   |
| --------------- | ----------------------------- |
| `<file>`        | Path to the backup `.db` file |
| `-y`, `--yes`   | Skip the confirmation prompt  |

**Usage with Docker:**

```bash
# Copy the backup into the data directory of the hub
cp ./backups/hub-export-20240101-120000.db ./data/hub/

# Stop the hub
docker compose stop hub

# Run import
docker compose run --rm hub import data/hub-export-20240101-120000.db

# Restart the hub
docker compose up -d hub
```

### key rotate

Re-encrypts all sensitive database fields with a new `APP_SECRET`. Use this when you need to rotate your encryption key.

<Callout type="warn">
	The Hub server must be **stopped** before rotating the key. Create a database backup first. If the
	rotation fails, restore the backup, keep the old `APP_SECRET`, and retry.
</Callout>

```bash
hub key rotate [--old-secret <secret>] [--yes]
```

| Flag           | Description                                                                   |
| -------------- | ----------------------------------------------------------------------------- |
| `--old-secret` | Previous `APP_SECRET` value. Can also be set via the `OLD_APP_SECRET` env var |
| `-y`, `--yes`  | Skip the confirmation prompt                                                  |

**Usage with Docker:**

```bash
# 1. Create a backup
docker compose exec hub /app/hub export

# 2. Stop the hub
docker compose stop hub

# 3. Rotate the key (set the NEW APP_SECRET in .env first)
docker compose run --rm \
  -e OLD_APP_SECRET=<old-secret> \
  hub key rotate

# 4. Restart the hub with the new APP_SECRET
docker compose up -d hub
```

After a successful rotation, all agent tokens and user sessions signed with the old secret are invalidated. Users need to log in again and agents need their tokens re-issued.

### reset-password

Resets a user's password and forces them to change it on the next login. See [Account Recovery](/docs/troubleshooting/account-recovery) for full details.

```bash
hub reset-password --email <email>
hub reset-password --id <user-id>
```

| Flag      | Description               |
| --------- | ------------------------- |
| `--email` | Email address of the user |
| `--id`    | ID of the user            |

Exactly one of `--email` or `--id` must be provided. Users that only log in via SSO can not be reset.

### version

Prints the version of the Hub. Also available as `--version`/`-v`.

### healthcheck

Checks whether the Hub is running and healthy. This is used by the Docker healthcheck of the image.

## Agent

The Agent CLI only provides the `version` and `healthcheck` commands. The `healthcheck` command is used by the Docker healthcheck of the image and reports the Agent as healthy once it is connected to the Hub.
